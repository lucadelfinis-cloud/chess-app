 CLAUDE.md

## About me
I'm not writing code. I'm learning to understand it at a high level. You write the code; I want to understand what's being built and why.

## After every change
End with a short summary that covers:

1. **Which files** you created, changed, or deleted.
2. **What each one does**, in plain English.
3. **Why it's needed**: what would break or be missing without it.

Guidelines:
- Keep it short. Plain English first, technical terms only when needed, and define them when you use them.
- Use analogies when they help (e.g. "this file is like the table of contents for the site").
- Don't explain syntax line by line unless I ask.

## NOTES.md
- Keep `NOTES.md` as a map of every file in the project and its purpose, one plain-English line per file.
- Update it whenever the structure changes (files added, removed, renamed, or a file's purpose changes).
- Mention in your summary when you've updated it.
